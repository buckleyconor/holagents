# Linter rules

Generated from `skills/guide-format/format.json` — do not edit by hand
(run `npm run docs:rules`). Rule config is the source of truth; rule logic
lives in `extensions/linter/rules/`.

| ID       | Severity | Check                                                                                                                                                                                                                                                                                                 | Fix hint                                                                                                      |
| -------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **L001** | error    | H1 with guide ID — First non-empty line must be `# <ID> <Title>` with the ID matching `HOL-\d{4}-\d{2}`.                                                                                                                                                                                              | Add `# HOL-XXXX-NN <Title>` as the first line of the guide.                                                   |
| **L002** | error    | Platform notice — The platform-notice line must appear verbatim within the first 3 non-empty lines.                                                                                                                                                                                                   | Insert the exact notice line near the top of the guide (see format spec).                                     |
| **L003** | error    | TOC present, sequential numbering — `## Table of Contents` must exist before the first module, and TOC entry numbers must be sequential 1..N.                                                                                                                                                         | Renumber TOC entries consecutively starting at 1.                                                             |
| **L004** | error    | TOC anchors resolve — Every TOC link must be a local anchor (`#…`) that resolves to an existing heading (GitHub anchor algorithm).                                                                                                                                                                    | Regenerate the anchor from the actual heading text; anchors must not be external URLs.                        |
| **L005** | error    | TOC coverage — Every non-TOC "##" section must appear in the TOC exactly once — matched by ANCHOR, not display title (house style uses short TOC titles, e.g. "Explore the VSS UI" for "## Module 1: Explore the VSS UI"). Duplicate "##" headings are also errors (ambiguous anchors).               | Add missing sections to the TOC and rename duplicate headings.                                                |
| **L006** | error    | Lab Credentials block — `### Lab Credentials:` (h3) must appear before the Introduction and contain at least one credential line.                                                                                                                                                                     | Use `### Lab Credentials:` (heading level 3) with at least one Username/Password/FQDN/IP line.                |
| **L007** | error    | Target Audience block — `### Target Audience` (h3) must exist before the Introduction.                                                                                                                                                                                                                | Add `### Target Audience` with the audience list before the Introduction section.                             |
| **L008** | error    | Introduction section — `## Introduction` must exist (variants such as `Introduction Overview` or `Orientation` are drift).                                                                                                                                                                            | Rename the section to exactly `## Introduction`.                                                              |
| **L009** | error    | Introduction markers — The Introduction must contain `**Duration:**` and `**Objective:**`.                                                                                                                                                                                                            | Add a `**Duration:**` line (estimated minutes) and an `**Objective:**` intro with bullet objectives.          |
| **L010** | error    | Summary section — A standalone `## Summary` section must exist (appendices may follow it). Out-of-order Summary is W003.                                                                                                                                                                              | Add a standalone `## Summary` section after the final module (do not fold it into a module heading).          |
| **L011** | error    | Module headings sequential — Body sections must match `## Module <N>: <Title>` with N sequential from 1. `## Phase …` and other variants are drift.                                                                                                                                                   | Rename body sections to `## Module <N>: <Title>` and keep numbering sequential.                               |
| **L012** | error    | Back-to-top link — Every `##` section ends with `[Back to top](#table-of-contents)`.                                                                                                                                                                                                                  | Add `[Back to top](#table-of-contents)` (optionally followed by `***`) at the end of the section.             |
| **L013** | error    | Image syntax — Every image line must be a platform ImageProxy line — ![alt](/ImageProxy?filename=<uuid>/<file> …) with any quote style and optional {data-modal=true} — or a << INSERT SCREENSHOT: … >> placeholder. Local or other-URL images fail (upload to the platform and link via ImageProxy). | Use the ImageProxy form for uploaded images, or the `<< INSERT SCREENSHOT: description >>` placeholder.       |
| **L014** | error    | Inline command shellcheck — Extracted inline commands (tab/4-space indented, backtick-wrapped) must pass shellcheck. Parse errors are errors; style warnings are W014.                                                                                                                                | Fix the flagged command (quote variables, drop unused pipes) or verify the line is not a command.             |
| **W001** | warning  | Callout style consistency — Non-standard or mixed callout variants detected (e.g. `**Tip!**`, `**Use Case!` alongside standard forms).                                                                                                                                                                | Use standard callouts: `**Tip:**`, `**Note:**`, `⚠️ **Important:**`, `**Use Case:**`, `> ✅ **Checkpoint:**`. |
| **W002** | warning  | Long section without subheading — A `##` section exceeds 400 lines with no `###` subheading (pacing risk).                                                                                                                                                                                            | Split the section into `###` sub-sections (e.g. per exercise or concept).                                     |
| **W003** | warning  | Summary ordering drift — A `## Summary` section exists but appears before at least one module (ordering drift).                                                                                                                                                                                       | Move `## Summary` after the final module.                                                                     |
| **W004** | warning  | Missing checkpoint — A module has 3 or more command steps but no `> ✅ **Checkpoint:**` block.                                                                                                                                                                                                        | Add a `> ✅ **Checkpoint:**` line stating the verifiable end state.                                           |
| **W005** | warning  | Image checklist mismatch — Module plan image checklist and the module's actual images/placeholders disagree (missing or extra).                                                                                                                                                                       | Reconcile the module plan image checklist with the screenshots actually present.                              |
| **W006** | warning  | Credential/URL drift — A credential or URL in a module body is not listed in the Lab Credentials block.                                                                                                                                                                                               | List every host/credential used in the guide in the Lab Credentials block (single source of truth).           |
| **W007** | warning  | Raw HTML in guide — Raw HTML (`<script`, `<iframe`, `onerror=`, `<img src=`) found — potential injection or platform rendering issue.                                                                                                                                                                 | Remove raw HTML; use the guide image syntax for images.                                                       |
| **W008** | warning  | Unfinished-marker tokens — `TODO`, `TBD`, or `FIXME` tokens found (image placeholders are excluded).                                                                                                                                                                                                  | Resolve or remove the marker before publishing.                                                               |
| **W014** | warning  | Inline command shellcheck style — A shellcheck style warning (not a parse error) on an extracted inline command.                                                                                                                                                                                      | Address the shellcheck finding (quote variables, avoid unused pipes) or verify the line is not a command.     |
| **W-SH** | warning  | shellcheck not installed — shellcheck binary not found; inline command checks were skipped.                                                                                                                                                                                                           | Install shellcheck (apt) for full L014 coverage.                                                              |

## Exit codes (CLI)

| Code | Meaning                  |
| ---- | ------------------------ |
| 0    | Clean (warnings allowed) |
| 1    | One or more errors       |
| 2    | Warnings only            |
| 3    | Usage/config error       |
